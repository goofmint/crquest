# ローカライズ

設定の「ユーザー」から表示言語を切り替えます。変更はセーブ後の再読み込みで反映されます。セーブに言語の設定がなければ、WebView の言語を使い、対応していなければ英語を使います。

## UI

`src/js/app/i18n/locales/` 内の JSON に UI の文言を追加します。言語間でキーと `{{name}}` のような補間変数をそろえてください。英語は既定の辞書です。新しい言語を追加する場合は、`languages.js` のレジストリと `index.js` の辞書の登録も更新します。

日本語の表示に Koromame を使うには、手元の `Koromame-Regular.woff2` または `Koromame-Regular.ttf` をリポジトリのルートに置きます。次の Tauri ビルドでアプリに組み込まれ、両方ある場合は WOFF2 が優先されます。OS にインストール済みの Koromame も利用できます。利用条件に従い、フォントファイルはリポジトリに含めません。

## 会話とミッション

翻訳は原本と同じディレクトリに置き、拡張子の前に言語コードを付けます。たとえば `greeting.pug` に対して `greeting.ja.pug`、`description.md` に対して `description.ja.md` を追加します。原本を提供した拡張機能から、その翻訳を読み込みます。翻訳が見つからない場合は原本を表示します。外部の拡張機能が原本を上書きした場合も、翻訳の提供元は同じ拡張機能です。

- Pug の翻訳では、ステートメントと選択肢の ID、分岐、状態更新、式を保持してください。相対 include は原本と同じ部分テンプレートを参照し、その翻訳があれば言語コード付きのファイル名を指定します。翻訳版の音声は言語コード付きの同名トラックを登録します。登録されていない翻訳版の音声は再生されません。
- Markdown では、解答、コード、コマンド、ファイルパス、API のパラメーター、リンク先、EJS タグをそのまま保持してください。英語での入力が必要な場合は、説明文でそのことを明示します。
- JSON の翻訳には表示用の値を記述します。目標の入力欄は既存の `name` で照合し、ラベルとプレースホルダーを翻訳します。
- バリデーターの `helper.t(key, english, vars)` とイベントの `world.t(key, english, vars)` は、同じディレクトリの `messages.ja.json` からキーを読み込みます。辞書にキーがなければ第2引数の英語を使います。補間は `{{name}}` 形式で、英語と翻訳で同じ変数を使います。

セーブ中のクエスト進捗を言語切り替え時に読み込むと、定義済みの初期文言と完全に一致するタイトルと説明だけが切り替わります。イベントで設定された独自の文言や完了フラグは維持されます。

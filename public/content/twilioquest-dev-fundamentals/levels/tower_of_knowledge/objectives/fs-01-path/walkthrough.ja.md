# ファイルパスとは？

コンピューターはデータをファイルに保存します。プレーンテキスト（通常は .txt）、音楽や動画（.mp3 や .mp4）、アプリケーションなど、さまざまな種類のファイルがあります。たくさんのファイルを整理するにはディレクトリ（フォルダー）が役立ちます。ディレクトリには、ファイルのほかに別のディレクトリも入れられます。

ファイルパスは、コンピューター上のファイルまでの道順です。目的のファイルにたどり着くまでに通るディレクトリが順番に並んでいます。コンピューター上のファイルやディレクトリには、それぞれパスがあります。

例えば、`portfolio` というディレクトリに `about_me.md` というファイルを作った場合、ファイルパスは次のようになります。
<%= `\`${formatPathPartsForOs('portfolio', 'about_me.md')}\``%>

実際に自分のコンピューターに作る場合は、パスがもっと長くなるでしょう。通常はユーザーアカウントの Documents フォルダーやホームディレクトリの中にファイルを作るので、それらのディレクトリもパスに含まれます。

`<%= isWindows ? `C:\\Users\\Cedric\\portfolio\\about_me.md`:`/home/Cedric/portfolio/about_me` %>`

パスの出発点になるディレクトリを **ルートディレクトリ** と呼びます。ファイルを木に見立てると、ルート（根）からいくつもの枝が伸びているように表せます。

## ファイルパスを使う

共同作業者にファイルの場所を知らせたり、コードから別のファイルを参照したりするときにファイルパスを使います。例えば、HTML でウェブサイトに画像を追加するときにもパスを指定します。

```
<img src="/images/cedric_headshot.png">
```

これは **相対パス** の例です。ルートからの完全なパスは **絶対パス** と呼ばれます。プロジェクト内では、ルートの代わりにプロジェクトを含むディレクトリを起点とする相対パスが使える場合がよくあります。

JavaScript テストラボや Python の神殿など、TwilioQuest のミッションではパスの入力を求められることがあります。後の課題で書くコードを TwilioQuest が見つけられるようにするためです。

## 課題をクリアする

セドリックのコンピューターにあるファイルとフォルダーをもう一度見てみましょう。

```plaintext
cedric/
├── robot_thoughts/
│ ├── real_boy.idea
│ └── youtube_video.mp4
│
├── thank_you_drafts/
│ ├── thank_you_toast.docx
│ ├── thank_you_toast_v1.docx
│ ├── thank_you_toast_v2.docx
│ └── thank_you_toast_v2_Final.docx
│
├── fog_owl_computations.csv
└── my_cool_drawing.png
```

これがファイルツリーです。`cedric/` は、ツリー内のほかのディレクトリやファイルをすべて含むルートディレクトリです。`robot_thoughts/` と `thank_you_drafts/` もディレクトリです。中にファイルがあり、末尾にはスラッシュが付いています。ファイルを入れられるのはディレクトリです。セドリックの YouTube 動画は `robot_thoughts/` の中にあります。

多くのファイルには、ファイルの種類を示す拡張子が付いています。セドリックの YouTube 動画の拡張子は「.mp4」です。この拡張子から動画ファイルだと分かり、コンピューターは開くのに適したプログラムを選べます。

パスを求めるには、ルートから目的のファイルまでツリーをたどり、通ったディレクトリを順に並べます。パスの最後は `youtube_video.mp4` です。ディレクトリとファイルの区切りにはスラッシュを使います。

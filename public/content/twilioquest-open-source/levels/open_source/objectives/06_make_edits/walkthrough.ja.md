# ピクセルを追加しよう

プロジェクトをローカルにコピーして開発ブランチを作ったので、いよいよ貢献する準備が整いました。まずプロジェクトをセットアップし、動かしてみましょう。こうすれば、GitHub に変更を公開する前に自分のコンピューターで確認できます。

## Node.js and NPM

Open Pixel Art プロジェクトは Node.js で動き、`npm` も使います。ここからは `npm` の使い方を知っていて、インストール済みであることを前提に進めます。

ツールに慣れていなければ、[Node.js のインストールガイド](https://www.taniarascia.com/how-to-install-and-use-node-js-and-npm-mac-and-windows/)に従ってください。Node.js をインストールしたら、この目標に出てくる `npm` コマンドはコピーして使えます。

## プロジェクトの依存関係をインストールする

Node.js と `npm` をインストールしたら、Open Pixel Art プロジェクトのルートフォルダーで次のコマンドを実行します。

```
npm install
```

プロジェクトの実行に必要な依存関係がコンピューターにダウンロードされます。インストール中は進行状況が表示されます。

処理にはしばらく時間がかかることがあります。

## 起動しよう

インストールと設定が済んだら、ローカルでプロジェクトを起動します。リポジトリのルートディレクトリで次のコマンドを実行してください。

```
npm start
```

コンピューター上でローカルウェブサーバーが起動し、自分の Open Pixel Art プロジェクトが動きます。起動後、ターミナルに通常次のような URL が表示されます。

```url
http://localhost:8080
```

ウェブブラウザーでこのページを開くと、ローカルで動いている自分の Open Pixel Art が見られます。

## Pixels.json

ローカルでピクセルを見られるようになったので、変更してみましょう。好きなテキストエディターで Open Pixel Art プロジェクトを開き、`_data/pixels.json` ファイルを開きます。

このファイルには、次のようなピクセルオブジェクトの JSON 配列が入っています。

```diff
{
  "data": [
    { "y": 1, "x": 1, "color": "#F22F46", "username": "<UNCLAIMED>" },
    { "y": 1, "x": 2, "color": "#F22F46", "username": "<UNCLAIMED>" },
    { "y": 1, "x": 3, "color": "#F22F46", "username": "<UNCLAIMED>" },
    ...
  ]
}
```

## ピクセルオブジェクトのプロパティ

- `x`：ピクセルの x 座標。0 は一番左の列です。
- `y`：ピクセルの y 座標。0 は一番下の行です。
- `color`：ピクセルの色を示す16進数コード。たとえば赤は #ff0000 です。
- `username`：プルリクエストを作るときに使う GitHub のユーザー名です。

次の例を参考に、`_data/pixels.json` に行を追加します。`username` の値 `cedric` は例なので、自分の GitHub ユーザー名に置き換えてください。

```diff
{
  "data": [
+    { "y": 1, "x": 2, "color": "#FFFF00", "username": "cedric" },
    { "y": 1, "x": 3, "color": "#F22F46", "username": "<UNCLAIMED>" },
    ...
  ]
}
```

ローカルの URL を開くと、追加したピクセルが見えるはずです！

## 並び順を保とう

追加したピクセルが `_data/pixels.json` の並び順を崩さないよう、`y`、次に `x` の順で並べてください。この作業を行う npm タスクも用意されています。

```bash
npm run sort:open-pixels
```

新しいピクセルを追加したら、このコマンドをターミナルで実行してファイルを並べ替えてください。

## 正常に動くか確かめよう

変更を終える前に、最後の `npm` コマンド、`npm test` を実行します。多くのオープンソースプロジェクトには自動テストがあります。変更でプロジェクトを壊していないか確認するために役立ちます。

ターミナルの新しいタブかウィンドウを開き、ローカルの Open Pixel Art リポジトリのルートディレクトリに移動してから、次のコマンドを実行してください。

```
npm test
```

すべてのテストに `passed` と表示され、失敗したものがなければ、変更後も正常に動いています。

## 変更を確定するには？

ついにキャンバスにピクセルを追加し、問題がないことも確認できました！

次に、この変更を確定することを `git` に伝えます。その操作が `commit` です。コミットはその時点のコードベースを記録したスナップショットです。

## コミットするには？

最初に、コミットするファイルを追加します。変更したいファイルだけを追加するので、今回は更新した `_data/pixels.json` だけです。

```
git add _data/pixels.json
```

正しいファイルを追加したか確認するには、次のコマンドを実行します。

```
git status
```

これからコミットするファイルが緑色で表示されます。表示されるファイルは `_data/pixels.json` だけのはずです！

`git commit` コマンドで変更を確定します。コミットにメッセージを添えるため、`-m` フラグも指定します。

メッセージに `feat(pixels):` を付けると、Open Pixel Art プロジェクトがコミットメッセージを自動で解析できます。詳しくは [Conventional Commits の仕様](https://www.conventionalcommits.org/en/v1.0.0-beta.4/)をご覧ください。

```
git commit -m "feat(pixels): add my new pixel"
```

# マージしよう

## マージとは？

マージは、Git で2つのブランチを一つにまとめることです。リポジトリをフォークしてブランチを作成したとき、新しいコードを含む別の履歴が生まれました。マージでその履歴を元のプロジェクトに組み込むと、誰もがそのコードを使えるようになります。

## 協力しよう

オープンソースプロジェクトにプルリクエストを作ったら、コードをマージできるように、そのプロジェクトのメンテナーと協力します。

Open Pixel Art では、ツールがプルリクエストの内容をチェックし、問題がなければ自動でマージします。

## マージコンフリクト

GitHub で、マージコンフリクトが発生して自動でコードをマージできないと通知されることがあります。最終的なコードをどうするか、人が判断する必要があります。

たとえば、別々の開発者が同じ行を同時に変更したときに発生します。

[GitHub のマージコンフリクトに関する資料](https://help.github.com/en/articles/about-merge-conflicts)を参照してください。GitHub 上のエディターで解消できることもあれば、新しいコミットをプッシュする必要があることもあります。

## マージされたことを確認するには？

メンテナーとやり取りするときには、返事を待つ時間も必要です。相談して変更を反映すると、リポジトリの管理者が最終的にマージを判断します。

マージされると、[通知の設定](https://help.github.com/en/articles/about-notifications)に応じて GitHub から連絡があります。

ここではツールが[自分のプルリクエスト](https://github.com/twilio-labs/open-pixel-art/pull/<%= env.TQ_OPEN_PIXEL_ART_PR_NUMBER.value %>)を自動でレビューするので、数分後に確認すればマージされているはずです！
